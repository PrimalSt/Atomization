# Генератор отчётов по контекстной рекламе

Собирает статистику рекламного кабинета (Яндекс Директ), валидирует её, агрегирует
по кампаниям и рендерит презентацию для клиента по YAML-конфигу. Работает как десктопное
приложение для Windows (`app_gui.py`, сборка в `.exe`) и как консольная утилита (`main.py`).
Ежемесячные выгрузки принимаются в Excel (`.xlsx`, `.xls`), CSV и JSON; колонки с другими
названиями сопоставляются через конфиг, а локальная история (SQLite) даёт на слайдах
динамику к прошлому месяцу (MoM).

## Структура

```
.
├── config/
│   └── report_config.yaml   # клиент, период, валюта, тема, слайды, маппинг колонок
├── output/                  # сгенерированные отчёты (в git не попадают)
├── local_storage/           # history.db — история помесячных итогов (создаётся сама, в git не попадает)
├── app_gui.py               # десктопное приложение: python app_gui.py
├── build_exe.py             # сборка .exe через PyInstaller: python build_exe.py
├── main.py                  # CLI: python main.py --help
├── src/
│   ├── pipeline.py          # generate_report(): конфиг → данные → агрегация → презентация
│   ├── schemas.py           # Pydantic-модели: данные, агрегаты, конфиг, выводы специалиста
│   ├── data_loader.py       # выгрузки (Excel/CSV/TSV/JSON), маппинг колонок, тестовые данные
│   ├── storage.py           # SQLite-история помесячных итогов для динамики MoM
│   ├── direct_client.py     # Reports API Яндекс Директа: запрос, очередь отчётов, разбор TSV
│   ├── config_loader.py     # чтение и валидация report_config.yaml
│   ├── paths.py             # пути из исходников и из собранного .exe
│   ├── console.py           # UTF-8 в консоли Windows, цвета, формат логов
│   ├── gui/
│   │   ├── app.py           # окно на customtkinter, сборка отчёта в отдельном потоке
│   │   └── tasks.py         # логика окна без tkinter: проверка ввода, рабочий поток, открытие файлов
│   └── rendering/
│       ├── builder.py       # build_presentation() — точка сборки
│       ├── theme.py         # HEX → RGBColor, палитра и шрифты из theme
│       ├── formatting.py    # числа, валюта, проценты
│       ├── primitives.py    # сетка слайда 16:9, текст, карточки, заголовок, подвал
│       ├── context.py       # данные для слайдов: итоги, динамика по дням, период
│       └── slides/          # фабрика + рендерер на каждый тип слайда
├── tests/                   # fixtures/ — книга Excel 97–2003 для тестов .xls
├── requirements.txt
└── requirements-dev.txt     # + pytest и PyInstaller
```

Поток данных: `data_loader` (маппинг колонок по `column_mapping`) → `DailyAdRecord` →
`aggregate_by_campaign` → `CampaignSummary` → `build_presentation` (по `ReportConfig.active_slides`,
с итогами прошлого месяца из `storage`) → `output/*.pptx`. Весь цикл связывает
`src.pipeline.generate_report`; входы — окно `app_gui.py` и консольный `main.py`.

## Десктопное приложение

```bash
python app_gui.py
```

Окно по шагам:

1. **Клиент и конфиг отчёта** — выпадающий список YAML-файлов из папки `config/`. Под ним —
   клиент, период и число слайдов из конфига или причина, по которой конфиг не прошёл
   валидацию. Новый конфиг клиента: скопируйте `report_config.yaml` под другим именем
   и нажмите «Обновить список».
2. **Выгрузка рекламного кабинета** — «Обзор...» для `.xlsx`, `.xls`, `.csv`, `.tsv`, `.json`
   или флажок «Использовать тестовые данные (Mock)». Флажок истории включает сохранение
   итогов месяца и динамику к прошлому месяцу (см. «История и динамика MoM»).
3. **Выводы специалиста** — текст в Markdown (формат — ниже, в «Формат выводов специалиста»)
   или «Загрузить заметки из файла...» (`.md`, `.txt`).
4. **«Сгенерировать презентацию (.pptx)»** — сборка идёт в отдельном потоке (`threading.Thread`),
   окно не замирает. Индикатор и строка статуса показывают этапы: «Чтение конфига»,
   «Чтение данных», «Агрегация», «Рендеринг». Предупреждения пайплайна (неполный период,
   CampaignId из названий и т. п.) видны в журнале внизу окна.
5. После сборки — окно «Презентация сохранена» с кнопками **«Открыть отчёт»** (файл откроется
   в PowerPoint) и **«Открыть папку»**; те же кнопки остаются в главном окне.

Отчёты сохраняются в `output/` (имя — из клиента и периода). Тема оформления — системная,
светлая или тёмная, переключатель в правом верхнем углу.

## Excel-выгрузки и маппинг колонок

Поддерживаются `.xlsx` / `.xlsm` (openpyxl) и старый `.xls` Excel 97–2003 (xlrd). Формат
определяется по содержимому, поэтому `.xlsx`, сохранённый с расширением `.xls`, тоже читается.
Берётся первый лист, на котором есть таблица; строки над ней (название отчёта, период,
фильтры) и пустые строки пропускаются. Заголовком считается первая из первых 30 непустых строк,
где с учётом маппинга есть хотя бы три колонки Директа. Даты — ячейки-даты Excel,
`2026-08-24` или `24.08.2026`.

Если колонки в файле называются иначе, чем в Директе, сопоставьте их в секции
`column_mapping` конфига — загрузчик переименует их до валидации строк:

```yaml
column_mapping:
  "Дата": "Date"
  "Направление": "CampaignName"
  "Показы": "Impressions"
  "Клики": "Clicks"
  "Затраты": "Cost"
  "Заявки": "Conversions"
  "ID кампании": "CampaignId"   # необязательная колонка
```

- Слева — название колонки в файле, справа — одна из колонок Директа: `Date`, `CampaignId`,
  `CampaignName`, `Impressions`, `Clicks`, `Cost`, `Conversions`. Опечатка справа — ошибка
  валидации конфига при загрузке.
- Регистр и лишние пробелы в названиях не важны: `"Затраты"` найдёт и «затраты », и «ЗАТРАТЫ».
- Колонки, уже названные как в Директе, сопоставлять не нужно; остальные колонки файла
  (например, «CTR, %») игнорируются.
- Две колонки файла не могут вести в одну колонку Директа — это ошибка конфига. Если в файле
  есть и `Cost`, и сопоставленная с ним «Затраты», загрузка остановится с номером строки.
- Маппинг действует для всех форматов файлов (Excel, CSV, JSON), секция необязательна.
  Если обязательной колонки нет, сообщение перечислит недостающие и колонки файла.

## История и динамика MoM

Итоги каждого отчёта сохраняются в локальную базу SQLite `local_storage/history.db`
(в собранном приложении — рядом с `.exe`). Таблица `monthly_snapshots`:

| Колонка | Что хранит |
|---|---|
| `client_id`, `report_month` | клиент (`client_name` из конфига) и месяц `YYYY-MM` — ключ записи |
| `total_spend`, `total_clicks`, `total_impressions`, `total_conversions` | суммы по всем кампаниям |
| `avg_cpa`, `avg_ctr` | CPA и CTR (%) от сумм; `NULL`, если не определены |
| `created_at`, `updated_at` | первое сохранение и последнее обновление |

- **Месяц отчёта** — тот, на который приходится больше дней периода: выгрузка за август —
  `2026-08`, скользящие 30 дней с 23.08 по 21.09 — `2026-09`.
- Повторная сборка за тот же месяц **обновляет** запись (UPSERT): исправленная выгрузка
  заменяет старые цифры.
- **Динамика** считается к предыдущему календарному месяцу. Если его нет в истории,
  карточки KPI показывают прежние подписи (формулу или среднее за день). Если есть —
  подпись вида «▲ 12,4% к августу»: для CTR и CR — разница в п.п., для остальных —
  изменение в процентах. Зелёный — к лучшему (для CPA и CPC — снижение), красный —
  к худшему, расход — нейтрально.
- Тестовые данные (Mock) в историю не пишутся. Если период не совпадает с календарным
  месяцем, в журнале будет предупреждение. Сбой базы не мешает собрать отчёт:
  он соберётся без динамики, а причина попадёт в журнал.

В окне история включена флажком (по умолчанию включён), в консоли — флагом `--history`.
Из Python:

```python
from src.storage import get_previous_month_metrics, save_monthly_metrics

save_monthly_metrics("ООО Доставка Плюс", "2026-08", summaries)          # list[CampaignSummary]
previous = get_previous_month_metrics("ООО Доставка Плюс", "2026-09")    # dict за 2026-08 или None
```

## Сборка .exe

На Windows, в окружении с `pip install -r requirements-dev.txt`:

```bash
python build_exe.py              # dist\AutoReport\AutoReport.exe — папка, быстрый запуск
python build_exe.py --onefile    # dist\AutoReport.exe — один файл, запускается медленнее
python build_exe.py --icon app.ico
```

Сборка идёт через PyInstaller с `--windowed` (без чёрного окна консоли). В бандл попадают
конфиги из `config/`, темы и шрифты customtkinter и шаблоны python-pptx. Рядом с `.exe`
скрипт кладёт папку `config/` — там правятся и добавляются конфиги клиентов; `output/`
и `local_storage/` приложение создаёт там же. Поэтому распакуйте сборку в папку с правом
записи (не в `Program Files`), а для передачи на другой компьютер архивируйте всю папку
`dist\AutoReport`. PyInstaller не делает кросс-компиляцию: на Linux и macOS получится
исполняемый файл для этой ОС.

## Запуск из консоли

```bash
# Синтетические данные за период из конфига → output/report_<клиент>_<период>.pptx
python main.py --mock

# Статистика напрямую из кабинета Яндекс Директа (см. раздел «API Яндекс Директа»)
python main.py --direct --notes-file notes.md

# Выгрузка кабинета (.xlsx, .xls, .csv, .tsv, .json) и короткий вывод специалиста
python main.py -i export.csv -n "CPA снизился на 12 % за счёт отключения площадок РСЯ"

# Ежемесячная выгрузка Excel: итоги сохраняются в историю, на слайдах — динамика к прошлому месяцу
python main.py -i export_2026-09.xlsx --history

# Несколько пунктов прямо в командной строке: \n — перенос строки
python main.py -i export.csv -n "- Отключили площадки с CPA выше 3 000 ₽\n- Тестируем новые объявления"

# Развёрнутые выводы — из файла .md/.txt; свой конфиг и путь к отчёту
python main.py -i export.json --notes-file notes.md -c config/client_b.yaml -o reports/client_b.pptx

# Воспроизводимые синтетические данные: 6 кампаний, фиксированное зерно
python main.py --mock --campaigns 6 --seed 42
```

| Флаг | Назначение |
|---|---|
| `-i`, `--input ФАЙЛ` | выгрузка кабинета: `.xlsx`, `.xls`, `.csv` (разделитель `,` или `;`), `.tsv`, `.json` |
| `--mock` | синтетические данные вместо файла |
| `--direct` | статистика из Reports API Директа за период из конфига |
| `-c`, `--config YAML` | конфиг отчёта, по умолчанию `config/report_config.yaml` |
| `-o`, `--output ПУТЬ` | папка (имя файла — из клиента и периода) или файл `.pptx`; по умолчанию `output/` |
| `-n`, `--notes ТЕКСТ` | выводы специалиста для слайда `notes_slide` |
| `--notes-file ФАЙЛ` | выводы из файла `.txt` / `.md` (UTF-8; cp1251 тоже читается) |
| `--history [DB]` | сохранить итоги месяца в историю и показать динамику MoM; по умолчанию `local_storage/history.db` |
| `--campaigns N`, `--seed N` | параметры синтетических данных, только с `--mock` |
| `-v`, `--verbose` | подробный лог (DEBUG): загрузка файлов, каждый слайд |
| `--no-color` | без цветов; они отключаются и сами при перенаправлении вывода или с `NO_COLOR` |

Источник данных — ровно один из `-i`, `--mock`, `--direct`.
Лог шагов идёт в stderr, итог (путь к отчёту, период, время по шагам) — в stdout,
поэтому путь можно забрать скриптом: `python main.py --mock 2>$null` (PowerShell).
Коды выхода: `0` — отчёт собран, `1` — ошибка входных данных (нет файла, невалидный
конфиг или выгрузка, ошибка API Директа, отчёт открыт в PowerPoint), `2` — неверные аргументы.

## API Яндекс Директа

`--direct` скачивает суточную статистику кампаний из [Reports API v5](https://yandex.ru/dev/direct/doc/reports/reports.html)
за период отчёта: `period_days` дней по вчерашний день включительно (или по `date_to` из конфига).

**Токен.** Нужен OAuth-токен с доступом к API Директа. Он берётся из переменной окружения
`YANDEX_DIRECT_TOKEN`, а если её нет — из файла `.env` в корне проекта:

```bash
copy .env.example .env          # Linux/macOS: cp .env.example .env
# впишите токен: YANDEX_DIRECT_TOKEN=y0_...
python main.py --direct
```

`.env` исключён из git. Не передавайте токен аргументом командной строки: он останется
в истории оболочки.

**Настройки** — секция `direct_api` конфига (вся секция необязательна):

```yaml
direct_api:
  client_login: "client-login"   # логин клиента, если токен агентский (заголовок Client-Login)
  goals: [12345678, 87654321]    # ID целей Метрики (до 10); пусто — общее поле Conversions
  include_vat: true              # расход с НДС (IncludeVAT)
```

С целями Директ возвращает конверсии отдельной колонкой на каждую цель
(`Conversions_<цель>_<модель атрибуции>`); в отчёт идёт их сумма по целям из конфига.

**Как идёт запрос.** `CAMPAIGN_PERFORMANCE_REPORT`, `CUSTOM_DATE`, формат TSV, суммы в
рублях (`returnMoneyInMicros: false`), `processingMode: auto`. Если отчёт в очереди
(HTTP 201/202), тот же запрос повторяется через `retryIn` секунд (по умолчанию 5), до
12 попыток; каждое ожидание видно в логе. Временные ошибки сервера (5xx) и сбои сети
тоже повторяются.

| Ошибка | Когда | Что делать |
|---|---|---|
| `DirectAuthError` | нет токена; HTTP 401/403; коды 53, 54, 58, 513 | проверить токен и `client_login` |
| `DirectLimitError` | HTTP 429; коды 56, 152, 506, 9000 (запросы, баллы, соединения, очередь) | повторить позже |
| `DirectReportTimeout` | отчёт не готов после 12 попыток | повторить запуск — Директ доформирует отчёт |
| `DirectApiError` | прочие ошибки запроса | текст ошибки Директа и `RequestId` — в сообщении |

Из Python — `generate_report(direct=True)` или сам клиент:

```python
from src.config_loader import load_report_config
from src.direct_client import SANDBOX_REPORTS_URL, fetch_campaign_report

records = fetch_campaign_report(load_report_config())                       # list[DailyAdRecord]
sandbox = fetch_campaign_report(load_report_config(), url=SANDBOX_REPORTS_URL)  # песочница Директа
```

### Формат выводов специалиста

Текст разбирается как упрощённый Markdown:

```markdown
# Итоги месяца
Расход вырос на **8 %** при стабильном CPA.

- Отключили площадки РСЯ с высоким CPA
- Добавили минус-слова

1. Запустить A/B-тест объявлений
2. Снизить ставки на брендовые запросы
```

`#` — заголовок, `-` / `*` / `•` — маркированный список, `1.` — нумерованный,
пустая строка разделяет абзацы, `**текст**` — полужирный. На слайде это настоящие
списки PowerPoint. Кегль (18 → 14 пт) и число колонок подбираются под объём текста;
если выводы не помещаются, они продолжаются на слайде «… (продолжение)». Без выводов
на слайде остаётся заготовка из `placeholder_text` конфига.

## Из Python

```python
from pathlib import Path

from src.pipeline import generate_report

result = generate_report(
    "config/report_config.yaml",
    input_path="export.xlsx",           # или mock=True, или direct=True
    notes=Path("notes.md"),             # Path — файл; str — текст; list[str] — пункты списка
    output="output/",
    history_db="local_storage/history.db",  # необязательно: история и динамика MoM
    on_progress=lambda step, total, name: print(f"{step}/{total} {name}"),

print(result.output_path, result.timing_summary(), result.compared_to)
```

Отдельные шаги тоже доступны: `load_ad_records`, `aggregate_by_campaign`, `build_presentation`.
Проверочные прогоны модулей: `python -m src.data_loader` (сводная таблица в консоль),
`python -m src.rendering.builder` (`output/report_test.pptx`).

## Соглашения

- **Имена полей.** В Python — snake_case, алиасы — как в Reports API Директа
  (`Date`, `CampaignId`, `Impressions`, `Cost`…). Строку выгрузки можно передавать
  в `DailyAdRecord.model_validate()` без переименований, а `model_dump(by_alias=True)`
  отдаёт ключи, на которые ссылается конфиг (`field: "CPA"`). Файлы с другими названиями
  колонок приводятся к этим именам через `column_mapping`.
- **Формулы.** CTR = клики / показы × 100 %, CPC = расход / клики,
  CPA = расход / конверсии, CR = конверсии / клики × 100 %. Итоги считаются от сумм
  (взвешенно), а не как среднее суточных значений.
- **Нулевой знаменатель.** Метрика равна `None` («не определена»), а не 0 и не `inf`:
  CPA = 0 выглядел бы как бесплатные лиды. В таблицах выводится «—».
- **Период.** По умолчанию заканчивается вчера, как `LAST_N_DAYS` в API Директа:
  статистика за сегодня ещё неполная.
- **Конфиг.** Неизвестный ключ, метрика или тип слайда — ошибка валидации при
  загрузке, а не при рендеринге. Порядок слайдов и метрик задаётся порядком в YAML;
  слайд отключается через `enabled: false`.
- **CampaignId в выгрузках.** Если колонки нет, ID выводится из названия кампании
  (blake2b, 13 знаков — не пересекается с 8–9-значными ID Директа). ID стабилен
  между запусками, но после переименования кампании станет другим.

## Презентация

- Формат 16:9 (13,333″ × 7,5″), цвета и шрифты — из `report_metadata.theme`.
- **Графики** — нативные диаграммы PowerPoint, данные редактируются в самом PowerPoint.
  Каждая серия получает свою диаграмму: расход и конверсии отличаются на порядки,
  а вспомогательной оси python-pptx не поддерживает. Подписи осей
  не зависят от региональных настроек зрителя: `40 000`, а не `40,000`.
- **Таблица** — кампании по убыванию расхода. Больше 10 кампаний — хвост сворачивается
  в строку «Прочие кампании». Ширина колонок подбирается под содержимое: числа не переносятся.
- **Подсветка `highlight_metric`** — отклонение от ориентира на 20 % и больше:
  для CTR/CPC/CPA/CR ориентир — значение по аккаунту, для счётчиков — среднее на кампанию.
  Зелёный — лучше, красный — хуже (для CPA и CPC меньше — лучше). Расход без
  конверсий подсвечивается в колонке CPA красным.
