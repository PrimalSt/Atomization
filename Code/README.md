# Генератор отчётов по контекстной рекламе

Микросервис собирает статистику рекламного кабинета (Яндекс Директ), валидирует её,
агрегирует по кампаниям и рендерит презентацию для клиента по YAML-конфигу.

## Структура

```
.
├── config/
│   └── report_config.yaml   # клиент, период, валюта, тема, набор и порядок слайдов
├── output/                  # сгенерированные отчёты (в git не попадают)
├── main.py                  # CLI: python main.py --help
├── src/
│   ├── pipeline.py          # generate_report(): конфиг → данные → агрегация → презентация
│   ├── schemas.py           # Pydantic-модели: данные, агрегаты, конфиг, выводы специалиста
│   ├── data_loader.py       # выгрузки кабинета (CSV/TSV/JSON) и генератор тестовых данных
│   ├── config_loader.py     # чтение и валидация report_config.yaml
│   ├── console.py           # UTF-8 в консоли Windows, цвета, формат логов
│   └── rendering/
│       ├── builder.py       # build_presentation() — точка сборки
│       ├── theme.py         # HEX → RGBColor, палитра и шрифты из theme
│       ├── formatting.py    # числа, валюта, проценты
│       ├── primitives.py    # сетка слайда 16:9, текст, карточки, заголовок, подвал
│       ├── context.py       # данные для слайдов: итоги, динамика по дням, период
│       └── slides/          # фабрика + рендерер на каждый тип слайда
├── tests/
├── requirements.txt
└── requirements-dev.txt
```

Поток данных: `data_loader` → `DailyAdRecord` → `aggregate_by_campaign` → `CampaignSummary`
→ `build_presentation` (по `ReportConfig.active_slides`) → `output/*.pptx`. Весь цикл
связывает `src.pipeline.generate_report`, консольный вход — `main.py`.

## Установка

Нужен Python 3.12+.

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
pytest                          # тесты
```

## Запуск из консоли

```bash
# Синтетические данные за период из конфига → output/report_<клиент>_<период>.pptx
python main.py --mock

# Выгрузка кабинета (.csv, .tsv, .json) и короткий вывод специалиста
python main.py -i export.csv -n "CPA снизился на 12 % за счёт отключения площадок РСЯ"

# Несколько пунктов прямо в командной строке: \n — перенос строки
python main.py -i export.csv -n "- Отключили площадки с CPA выше 3 000 ₽\n- Тестируем новые объявления"

# Развёрнутые выводы — из файла .md/.txt; свой конфиг и путь к отчёту
python main.py -i export.json --notes-file notes.md -c config/client_b.yaml -o reports/client_b.pptx

# Воспроизводимые синтетические данные: 6 кампаний, фиксированное зерно
python main.py --mock --campaigns 6 --seed 42
```

| Флаг | Назначение |
|---|---|
| `-i`, `--input ФАЙЛ` | выгрузка кабинета: `.csv` (разделитель `,` или `;`), `.tsv`, `.json` |
| `--mock` | синтетические данные вместо файла (взаимоисключающий с `-i`) |
| `-c`, `--config YAML` | конфиг отчёта, по умолчанию `config/report_config.yaml` |
| `-o`, `--output ПУТЬ` | папка (имя файла — из клиента и периода) или файл `.pptx`; по умолчанию `output/` |
| `-n`, `--notes ТЕКСТ` | выводы специалиста для слайда `notes_slide` |
| `--notes-file ФАЙЛ` | выводы из файла `.txt` / `.md` (UTF-8; cp1251 тоже читается) |
| `--campaigns N`, `--seed N` | параметры синтетических данных, только с `--mock` |
| `-v`, `--verbose` | подробный лог (DEBUG): загрузка файлов, каждый слайд |
| `--no-color` | без цветов; они отключаются и сами при перенаправлении вывода или с `NO_COLOR` |

Лог шагов идёт в stderr, итог (путь к отчёту, период, время по шагам) — в stdout,
поэтому путь можно забрать скриптом: `python main.py --mock 2>$null` (PowerShell).
Коды выхода: `0` — отчёт собран, `1` — ошибка входных данных (нет файла, невалидный
конфиг или выгрузка, отчёт открыт в PowerPoint), `2` — неверные аргументы.

### Формат выводов специалиста

Текст разбирается как упрощённый Markdown:

```markdown
# Итоги месяца
Расход вырос на **8 %** при стабильном CPA.

- Отключили площадки РСЯ с высоким CPA
- Добавили минус-слова

1. Запустить A/B-тест объявлений
2. Снизить ставки на брендовые запросы
```

`#` — заголовок, `-` / `*` / `•` — маркированный список, `1.` — нумерованный,
пустая строка разделяет абзацы, `**текст**` — полужирный. На слайде это настоящие
списки PowerPoint. Кегль (18 → 14 пт) и число колонок подбираются под объём текста;
если выводы не помещаются, они продолжаются на слайде «… (продолжение)». Без выводов
на слайде остаётся заготовка из `placeholder_text` конфига.

## Из Python

```python
from pathlib import Path

from src.pipeline import generate_report

result = generate_report(
    "config/report_config.yaml",
    input_path="export.csv",            # или mock=True
    notes=Path("notes.md"),             # Path — файл; str — текст; list[str] — пункты списка
    output="output/",
)
print(result.output_path, result.timing_summary())
```

Отдельные шаги тоже доступны: `load_ad_records`, `aggregate_by_campaign`, `build_presentation`.
Проверочные прогоны модулей: `python -m src.data_loader` (сводная таблица в консоль),
`python -m src.rendering.builder` (`output/report_test.pptx`).

## Соглашения

- **Имена полей.** В Python — snake_case, алиасы — как в Reports API Директа
  (`Date`, `CampaignId`, `Impressions`, `Cost`…). Строку выгрузки можно передавать
  в `DailyAdRecord.model_validate()` без переименований, а `model_dump(by_alias=True)`
  отдаёт ключи, на которые ссылается конфиг (`field: "CPA"`).
- **Формулы.** CTR = клики / показы × 100 %, CPC = расход / клики,
  CPA = расход / конверсии, CR = конверсии / клики × 100 %. Итоги считаются от сумм
  (взвешенно), а не как среднее суточных значений.
- **Нулевой знаменатель.** Метрика равна `None` («не определена»), а не 0 и не `inf`:
  CPA = 0 выглядел бы как бесплатные лиды. В таблицах выводится «—».
- **Период.** По умолчанию заканчивается вчера, как `LAST_N_DAYS` в API Директа:
  статистика за сегодня ещё неполная.
- **Конфиг.** Неизвестный ключ, метрика или тип слайда — ошибка валидации при
  загрузке, а не при рендеринге. Порядок слайдов и метрик задаётся порядком в YAML;
  слайд отключается через `enabled: false`.
- **CampaignId в выгрузках.** Если колонки нет, ID выводится из названия кампании
  (blake2b, 13 знаков — не пересекается с 8–9-значными ID Директа). ID стабилен
  между запусками, но после переименования кампании станет другим.

## Презентация

- Формат 16:9 (13,333″ × 7,5″), цвета и шрифты — из `report_metadata.theme`.
- **Графики** — нативные диаграммы PowerPoint, данные редактируются в самом PowerPoint.
  Каждая серия получает свою диаграмму: расход и конверсии отличаются на порядки,
  а вспомогательной оси python-pptx не поддерживает. Подписи осей
  не зависят от региональных настроек зрителя: `40 000`, а не `40,000`.
- **Таблица** — кампании по убыванию расхода. Больше 10 кампаний — хвост сворачивается
  в строку «Прочие кампании». Ширина колонок подбирается под содержимое: числа не переносятся.
- **Подсветка `highlight_metric`** — отклонение от ориентира на 20 % и больше:
  для CTR/CPC/CPA/CR ориентир — значение по аккаунту, для счётчиков — среднее на кампанию.
  Зелёный — лучше, красный — хуже (для CPA и CPC меньше — лучше). Расход без
  конверсий подсвечивается в колонке CPA красным.
